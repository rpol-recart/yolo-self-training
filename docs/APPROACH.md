# Self-training детектора YOLO на псевдоразметке — описание подхода

Документ описывает метод, который реализован в этом репозитории, и правила работы с ним.
Он не привязан к конкретной предметной области: классы объектов, источники данных и
пороги задаются в конфиге.

---

## 1. Задача и идея

**Ситуация:** есть небольшой набор изображений с ручной разметкой (сотни – единицы тысяч)
и большой пул неразмеченных изображений из того же домена (десятки–сотни тысяч, часто —
кадры видео). Размечать всё вручную дорого.

**Идея self-training (учитель → ученик):**

1. Обучаем детектор на ручной разметке — это **учитель**.
2. Учитель размечает неразмеченный пул. Оставляем только те предсказания, в которых он
   уверен, — это **псевдоразметка**.
3. Обучаем нового детектора (**ученика**) на «ручная разметка + псевдоразметка».
4. Если ученик лучше учителя на **честной** проверке — он становится новым учителем,
   цикл повторяется.

Ученик видит в разы больше примеров из домена (другие ракурсы, освещение, фоны), чем есть
в ручной разметке, и обобщает лучше. Типичный выигрыш — единицы процентов mAP и заметно
более устойчивое поведение на «редких» условиях. Главный риск — **закрепление ошибок
учителя** (confirmation bias): если учитель систематически ошибается, ученик выучит эти
ошибки ещё увереннее. Почти все правила ниже нужны, чтобы этот риск контролировать.

### Когда подход оправдан

- неразмеченных данных минимум в 5–10 раз больше, чем размеченных;
- базовая модель на ручной разметке уже работает прилично (mAP50 хотя бы ~0.5), иначе
  псевдоразметка будет слишком шумной;
- неразмеченные данные из того же распределения, что и боевые (те же источники, условия).

### Когда не поможет

- базовая модель плохо видит класс вообще (recall около нуля) — self-training не создаст
  знание, которого нет; нужна ручная разметка этого класса;
- ошибка систематическая (модель путает два класса) — ученик её унаследует; нужна ручная
  разметка трудных примеров (active learning, п. 7).

## 2. Данные: что нужно на входе

| Набор | Назначение | Правило |
| --- | --- | --- |
| **GT-train** | обучение учителя и всех учеников | ручная разметка |
| **GT-val** | калибровка порогов, приём/отказ раунда | ручная разметка, **никогда не попадает в обучение** |
| **GT-test** | финальная оценка, один раз в конце | ручная разметка, не используется для решений |
| **Неразмеченный пул** | источник псевдоразметки | не должен пересекаться по группам с val/test |

### 2.1. Группы и разбиение без утечки

**Группа** — единица, внутри которой кадры похожи друг на друга: одно видео, одна
камера, одна съёмочная сессия, один объект/площадка. Разбиение train/val/test делается
**по группам, а не по кадрам**. Если соседние кадры одного видео окажутся и в train, и в
val, метрика на val будет завышена и перестанет отличать хорошие раунды от плохих.

Группа задаётся регулярным выражением по пути файла (`groups.regex`, именованная группа
`(?P<group>...)`) или CSV-файлом `path,group`.

### 2.2. Разбиение замораживается

Сплит создаётся **один раз** и сохраняется в `workdir/splits/`. Все раунды используют
один и тот же GT-val. Если val меняется между раундами, метрики раундов несравнимы, и
можно «принять» раунд, который на самом деле хуже. При повторном запуске пайплайн
переиспользует сохранённый сплит.

### 2.3. Сколько размечать вручную

Ориентиры, не жёсткие правила:
- GT-val — не меньше 100–200 объектов каждого класса, из разных групп;
- GT-train — от нескольких сотен изображений; главное — покрыть все группы и условия;
- лучше меньше изображений из разных групп, чем много из одной.

## 3. Цикл раундов

```
          ┌──────────────── раунд 0 ────────────────┐
GT-train ─┤ обучение ученика с базовых весов → оценка на GT-val ├─► лучшая модель
          └──────────────────────────────────────────┘
                                   │
          ┌──────────────── раунд k ≥ 1 ─────────────────────────────────────┐
          │ 1. учитель = лучшая модель на данный момент                       │
          │ 2. предсказания учителя на GT-val  → калибровка порогов по классам │
          │ 3. предсказания учителя на пуле    → фильтрация псевдоразметки     │
          │ 4. датасет раунда = GT-train + псевдоразметка (с лимитами)          │
          │ 5. обучение ученика (по умолчанию — с базовых весов)                │
          │ 6. оценка на GT-val: общая и по группам                             │
          │ 7. правило приёма → ученик становится учителем или отбрасывается    │
          └───────────────────────────────────────────────────────────────────┘
                                   │
                  стоп: N раундов подряд без улучшения или max_rounds
                                   │
                    финальная оценка лучшей модели на GT-test
```

Всё это делает `python -m selftrain.loop --config <config.yaml>`. Каждый раунд пишет
свои артефакты в `workdir/rounds/<k>/`, итоговая история — `workdir/history.json`.
Прерванный цикл можно перезапустить: завершённые раунды пропускаются.

## 4. Псевдоразметка: как отбирать

### 4.1. Пороги уверенности калибруются по данным

Фиксированный порог (например 0.5 для всех классов) — частая ошибка: у разных классов
разное распределение уверенности. Порог выбирается **для каждого класса** по GT-val:

- учитель предсказывает на GT-val с низким порогом;
- предсказания сопоставляются с разметкой по IoU ≥ `calibration.iou` (по умолчанию 0.5);
- для каждого возможного порога считается точность (precision) предсказаний выше него;
- **верхний порог** `t_high` — минимальный порог, при котором precision ≥
  `calibration.target_precision` (по умолчанию 0.90);
- **нижний порог** `t_low` — минимальный порог, при котором precision ≥
  `calibration.low_precision` (по умолчанию 0.50).

Если все предсказания класса на val выше какого-то уровня верны, нижний порог
опускается до `teacher.conf_floor`: данных о том, что менее уверенные боксы — фон,
нет, поэтому они считаются серой зоной, а не фоном.

Если у класса мало примеров в val (`calibration.min_support`) или целевая точность не
достигается ни при каком пороге, используется запасной порог `calibration.fallback_high`
— это сигнал, что по классу нужна ручная разметка.

Пороги пересчитываются **в каждом раунде**, потому что у нового учителя другая
калибровка уверенности.

### 4.2. Три зоны уверенности

| Уверенность | Что делаем |
| --- | --- |
| ≥ `t_high` | бокс идёт в псевдоразметку |
| между `t_low` и `t_high` | «серая зона»: неизвестно, объект это или нет |
| < `t_low` | считаем фоном, игнорируем |

У YOLO нет «игнор-регионов». Если оставить изображение с объектом из серой зоны без
бокса, модель выучит «здесь нет объекта» — то есть ложный негатив. Поэтому по умолчанию
(`filter.uncertain_policy: drop_image`) **изображение с хотя бы одним боксом серой зоны
в обучение не идёт**, а попадает в очередь на ручную разметку (п. 7). Альтернатива
`keep_confident` оставляет такие изображения только с уверенными боксами — больше данных,
но выше риск ложных негативов.

### 4.3. Дополнительные фильтры

- **Минимальный размер бокса** (`filter.min_box_area`, доля площади кадра): мелкие боксы
  чаще всего ошибочны, и их ошибка сильнее всего бьёт по обучению.
- **NMS по классу** после предсказания (дубли от TTA).
- **Временная согласованность** (для кадров видео, `filter.temporal`): бокс остаётся,
  только если в соседних кадрах той же последовательности (±`window`) есть бокс того же
  класса с IoU ≥ `iou` не меньше чем в `min_support` кадрах. Отсекает одиночные
  «вспышки» ложных срабатываний. Последовательность и номер кадра берутся из пути файла
  регулярным выражением (`(?P<seq>...)`, `(?P<idx>\d+)`).
- **TTA учителя** (`teacher.tta: true`): предсказание по нескольким аугментациям
  (отражения, масштабы) даёт более стабильную уверенность. Медленнее, но учитель
  запускается один раз за раунд.

### 4.4. Фоновые изображения

Изображения пула, где учитель ничего не видит даже выше `t_low`, полезны как негативы:
они учат модель не срабатывать на фон. Их добавляется не больше
`merge.background_ratio` от числа изображений GT-train.

### 4.5. Баланс и лимиты

- **Доля псевдоразметки** ограничена: изображений с псевдоразметкой не больше
  `merge.max_pseudo_ratio` × размер GT-train (по умолчанию 3). Ручная разметка должна
  оставаться заметной частью обучения, иначе ошибки учителя доминируют.
- **Редкие классы в приоритете**: при отборе в первую очередь берутся изображения с
  боксами классов, которых меньше всего. Без этого частые классы «съедают» лимит, а
  редкие схлопываются.
- Лимит на число изображений из одной группы (`merge.max_per_group`), чтобы одна
  длинная последовательность не заполнила весь датасет.

## 5. Обучение ученика

- **С базовых весов, а не с весов учителя** (`student.init: base`). Если каждый ученик
  продолжает учителя, ошибки накапливаются из раунда в раунд. Обучение с одних и тех же
  предобученных весов даёт ученику шанс «не согласиться» с учителем там, где ручная
  разметка говорит иное. Вариант `student.init: teacher` быстрее, но выше риск дрейфа.
- Одинаковые гиперпараметры, `imgsz`, `seed` во всех раундах, чтобы различие в метрике
  объяснялось данными, а не настройками.
- Учитель может быть больше ученика (например, `m`/`l` учитель, `s`/`n` ученик для
  продакшена) — это стандартный и полезный вариант: размер учителя влияет только на
  качество псевдоразметки.

## 6. Оценка, приём раунда, остановка

### 6.1. Что меряем

- mAP50-95 и mAP50 на **GT-val**, общие и по классам;
- те же метрики **по каждой группе** (отдельный прогон валидации на подмножестве val).

Средняя метрика может расти за счёт «лёгких» групп и скрывать просадку на сложных.
Поэтому решение принимается и по группам.

### 6.2. Правило приёма

Раунд принимается, если одновременно:
1. `metric` (по умолчанию mAP50-95) ≥ лучшей метрики + `accept.min_delta`;
2. ни одна группа не просела относительно лучшей модели больше чем на
   `accept.group_tolerance`.

**Как выбрать `min_delta`.** Метрика YOLO заметно «шумит» от seed и порядка батчей:
на небольших val разброс между двумя одинаковыми запусками бывает 0.005–0.02 mAP.
Перед первым циклом обучите раунд 0 два-три раза с разными `seed` и поставьте
`min_delta` не меньше наблюдаемого разброса. Иначе будут приниматься раунды, которые
лучше только случайно. Поэтому же обучение всех раундов идёт с одним и тем же `seed`,
а меняется (на `seed + k`) только случайный отбор псевдоразметки.

Принятый ученик становится учителем следующего раунда. Отвергнутый — нет: следующий
раунд снова использует прежнего учителя. Пороги при этом не меняются (учитель и val те
же), меняется только случайный отбор псевдоразметки (`seed + k`), и то лишь когда
кандидатов больше лимита `max_pseudo_ratio`. Если набор данных раунда получился
таким же, как у отвергнутого, цикл останавливается сразу: повторное обучение дало бы
тот же результат. Поэтому `loop.patience > 1` имеет смысл, только когда лимит
псевдоразметки реально срабатывает или используется `student.init: teacher`.

### 6.3. Остановка

- `loop.patience` раундов подряд без приёма;
- или достигнут `loop.max_rounds`.

На практике основная польза приходит в первых 1–3 раундах. **Нормальная ситуация —
лучшим оказывается один из первых раундов**, а дальнейшие не дают прироста или
ухудшают. Поэтому финальной моделью считается лучшая по правилу приёма, а не последняя.

### 6.4. GT-test

GT-test используется **один раз**, в конце, для отчёта. Если по нему выбирать раунд или
пороги, он превращается во второй val и перестаёт быть честной оценкой.

## 7. Связь с ручной разметкой (active learning)

Каждый раунд пишет `workdir/rounds/<k>/review_queue.csv` — изображения с боксами серой
зоны, отсортированные по неопределённости и распределённые по группам. Это лучшие
кандидаты на ручную разметку: модель на них сомневается.

Рекомендуемый ритм:
1. Прогнать 1–3 раунда self-training.
2. Разметить вручную 100–300 изображений из очереди (например в CVAT; предсказания
   учителя можно подгрузить как пред-разметку).
3. Добавить их в **GT-train** (не в val!), перезапустить цикл с раунда 0.

GT-val пополнять можно, но только осознанно и с пересчётом метрик **всех** сравниваемых
моделей на новом val.

## 8. Типовые ошибки

| Ошибка | Симптом | Что делать |
| --- | --- | --- |
| Утечка между train и val (сплит по кадрам) | val-метрика высокая, на новых данных хуже | сплит по группам (п. 2.1) |
| Val меняется между раундами | метрики раундов «прыгают», нельзя сравнить | замороженный сплит (п. 2.2) |
| Один порог на все классы | у одного класса много ложных, у другого — пропуски | калибровка по классам (п. 4.1) |
| Серая зона без бокса | recall ученика падает | `drop_image` (п. 4.2) |
| Слишком много псевдоразметки | ученик повторяет ошибки учителя | `max_pseudo_ratio` (п. 4.5) |
| Редкий класс исчезает | AP редкого класса падает от раунда к раунду | приоритет редких классов, ручная разметка |
| Ученик с весов учителя | медленный дрейф качества | `student.init: base` (п. 5) |
| Выбор модели по test | завышенная итоговая оценка | test только в конце (п. 6.4) |
| Пул из другого распределения | прироста нет | пул из тех же источников, что и боевые данные |

## 9. Чек-лист одного запуска

1. [ ] Ручная разметка в формате YOLO (`images/…`, `labels/…`, один `.txt` на изображение).
2. [ ] Проверить регулярное выражение групп на своих путях:
       `python -m selftrain.split --config cfg.yaml --dry-run` — печатает группы и их размеры.
3. [ ] Сплит создан и заморожен (`workdir/splits/`), группы val/test не пересекаются с train.
4. [ ] Базовые веса выбраны (`student.base_weights`), `imgsz` соответствует размеру объектов.
5. [ ] Прогнать `make smoke` на синтетике — убедиться, что окружение рабочее.
6. [ ] Запустить цикл: `python -m selftrain.loop --config cfg.yaml`.
7. [ ] После каждого раунда посмотреть `rounds/<k>/thresholds.json` (не слишком ли низкие
       пороги), `rounds/<k>/pseudo_stats.json` (сколько боксов по классам),
       `rounds/<k>/metrics.json` (общие и по группам).
8. [ ] Визуально проверить 30–50 случайных псевдоразмеченных изображений раунда 1.
       Если ошибок больше ~10% — поднять `target_precision`.
9. [ ] По `history.json` выбрать лучшую модель; прогнать финальную оценку на GT-test.
10. [ ] Отдать `review_queue.csv` на ручную разметку, пополнить GT-train, повторить.

## 10. Справочник параметров

Все параметры с комментариями — в `configs/default.yaml`. Ключевые:

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `names` | — | список классов (порядок = индекс класса в YOLO-метках) |
| `groups.regex` | — | регулярное выражение с `(?P<group>…)` по относительному пути |
| `split.val_fraction` / `test_fraction` | 0.15 / 0.15 | доли групп в val/test |
| `teacher.conf_floor` | 0.05 | минимальный порог при предсказании учителя |
| `teacher.tta` | true | TTA при псевдоразметке |
| `calibration.target_precision` | 0.90 | точность для `t_high` |
| `calibration.low_precision` | 0.50 | точность для `t_low` |
| `filter.uncertain_policy` | drop_image | что делать с серой зоной |
| `filter.min_box_area` | 0.0005 | минимальная площадь бокса (доля кадра) |
| `filter.temporal.enabled` | false | фильтр согласованности по соседним кадрам |
| `merge.max_pseudo_ratio` | 3.0 | лимит псевдо-изображений относительно GT-train |
| `merge.background_ratio` | 0.1 | доля фоновых изображений |
| `student.init` | base | с каких весов учится ученик |
| `accept.metric` | map50_95 | метрика приёма |
| `accept.min_delta` | 0.003 | минимальный прирост |
| `accept.group_tolerance` | 0.02 | допустимая просадка группы |
| `loop.max_rounds` / `patience` | 4 / 2 | ограничения цикла |

## 11. Воспроизводимость

- фиксированный `seed` (обучение, отбор псевдоразметки, сплит);
- версии зависимостей закреплены в `requirements.txt`;
- каждый раунд сохраняет свой конфиг (`rounds/<k>/config.yaml`), пороги, статистику
  псевдоразметки, список изображений датасета и метрики — по ним можно восстановить,
  на чём обучена любая модель.

## 12. Глоссарий

- **Учитель / ученик** — модель, которая размечает / модель, которая учится на её разметке.
- **Псевдоразметка** — разметка, сделанная моделью, а не человеком.
- **Группа** — единица стратификации (видео, камера, сессия), внутри которой данные коррелированы.
- **Серая зона** — предсказания с уверенностью между нижним и верхним порогом.
- **TTA** — test-time augmentation, усреднение предсказаний по аугментациям.
- **mAP50-95** — средняя точность детекции, усреднённая по порогам IoU от 0.5 до 0.95.
